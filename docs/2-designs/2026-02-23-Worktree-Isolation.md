## Problem

The swarm plugin dispatches read-only Explore agents. It cannot handle tasks
that require file edits because all specialists share the main working
directory. The new `isolation: worktree` frontmatter field in Claude Code
enables subagents to run in isolated git worktrees, each with their own copy
of the repository.

## Decision

Add optional `isolation` field support to the swarm role schema. When a role
specifies `isolation: worktree`, the dispatch logic passes this to the Task
tool and auto-upgrades `subagent_type` to `general-purpose` (since Explore
agents cannot write files). Include one example writable role (`implementer`)
and a new preset.

## Scope

- Add `isolation` field to role schema in `swarm-roles.yaml`
- Update dispatch logic in `SKILL.md` step 6 to handle isolation
- Add `implementer` role with `isolation: worktree`
- Add `implement-and-review` preset
- Update "When NOT to Use" section (remove v2 blocker for file edits)
- Update `README.md` to document isolation support
- Keep existing read-only roles unchanged

## Architecture

### Role Schema Extension

Optional `isolation` field per role in `swarm-roles.yaml`:

```yaml
roles:
  implementer:
    description: "Implement code changes in an isolated worktree"
    subagent_type: general-purpose
    isolation: worktree
    model: sonnet
    prompt: |
      ...
```

Valid values: `worktree` or absent (no isolation).

### Auto-Upgrade Behavior

When `isolation: worktree` is set on a role:

1. If `subagent_type` is `Explore` or absent, override to `general-purpose`
2. Log a note: `Role {name}: using general-purpose (worktree isolation)`
3. Pass `isolation: "worktree"` to the Task tool call

This auto-upgrade is non-blocking. The dispatch prints a note but does not
prompt the user for confirmation.

### Dispatch Logic (SKILL.md Step 6)

The spawn step gains conditional handling:

```text
For each role:
  - Read isolation field from role config
  - If isolation: worktree:
      - Override subagent_type to general-purpose (if Explore or absent)
      - Log: "Role {name}: using general-purpose (worktree isolation)"
      - Pass isolation: "worktree" to Task tool
  - Otherwise: use existing subagent_type (default: Explore), no isolation
```

### New Role: implementer

```yaml
implementer:
  description: "Implement code changes in an isolated worktree"
  subagent_type: general-purpose
  isolation: worktree
  prompt: |
    You are an implementation specialist working in an isolated worktree.
    You have full read/write access to the repository.

    For your assigned task:
    - Read and understand the relevant code
    - Make the requested changes
    - Verify your changes work (run tests if applicable)
    - Commit your changes with a clear commit message

    Report what you changed and any issues encountered.

    Send your findings to the team lead when complete.
```

### New Preset: implement-and-review

```yaml
implement-and-review:
  description: "Implementation with concurrent review"
  roles: [implementer, quality-reviewer]
```

### Design Constraints Update

Remove `Tasks requiring file edits (v2 -- not yet supported)` from the
"When NOT to Use" section. Replace with guidance that writable roles require
`isolation: worktree` to prevent conflicts.

## Worktree Lifecycle

Claude Code manages worktree lifecycle automatically:

- Created when the Task tool spawns the subagent with `isolation: worktree`
- Located under `<repo>/.claude/worktrees/<auto-generated-name>/`
- Cleaned up automatically if no changes were made
- If changes exist, the worktree path and branch are returned in the result

The swarm lead does not need to manage worktrees directly.
